## Changes

- Improve basic inbound spam filtering with decoded visible HTML text, entity
  and whitespace normalization, GTUBE detection, more dangerous attachment
  suffixes, and more precise form and shortened-link checks. Spam continues to
  go to Junk with its score and reasons. Webmail adds **Mark as junk** and
  **Not junk** actions. These actions move the message; they do not train a
  classifier or change sender rules.
- Host up to 50 mail domains with the existing primary `domain` and new
  `additional_domains`. Login, account creation, invitations, SMTP, local
  delivery, forwarding, client discovery and DNS guidance support each domain.
  Mailboxes with the same prefix on different domains remain independent.
- Sign outgoing mail using its actual From domain. Hosted domains share the
  configured DKIM key and selector; publish the displayed DKIM record under
  every domain before sending from it.
- Recognize more verification codes, including grouped digits and codes split
  across HTML elements, while rejecting unrelated numbers and ambiguous
  candidates. Recognize account verification, activation and sign-in links in
  decoded visible mail. Webmail displays the destination and opens links only
  when clicked.
- Keep the existing verification-code API response by default. Clients can opt
  into code-or-link results with `include_links=true`, using the same owner
  restriction, `codes:read` permission, recent-mail window and unread-state
  preservation.

## Upgrading

PostPlus **0.3.1 and newer** can update directly. The updater replaces changed
modules while preserving configuration, accounts, mail, queues, certificates
and keys. Existing single-domain configurations need no changes. Keep a private
backup before upgrading.

Add domains under **Administration → Server settings → Additional mail domains**.
Publish MX, SPF, DKIM and DMARC for each domain using the DNS page's domain
selector. The server hostname and TLS certificate remain shared. Removing a
domain does not delete its accounts or mail; invitations for it become inactive.
Prefix-only forwarding rules continue to belong to the primary domain; use a
full pattern such as `sales-*@example.net` to target an additional domain.

Built-in spam rules do not authenticate senders. Rspamd remains optional and
incoming SPF/DKIM/DMARC verification is not added by this release. Verification
link recognition does not establish that a message or destination is trustworthy.

Installations running **0.3.0** must first install
[0.3.1](https://github.com/TabNahida/PostPlus/releases/tag/v0.3.1) manually.
