## Changes

- Fix upgrades from 0.5.0 being blocked by "This hostname is not configured for this portal." Missing or empty `admin_hostname` preserves compatibility access, including after first-run setup. Enable login hostname restrictions and explicitly save an administration hostname to activate isolation; the checkbox prefills the first mail domain for review.
- Bind a mailbox domain to its own Webmail hostname, for example `@a.com` accounts at `mail.a.com`. Login, API keys, invitations and public address inputs follow the mailbox domain behind the binding. Shared Webmail remains optional.
- Consolidate DNS guidance, checks and TLS certificate management in **Domains**. Each domain has its own access-hostname binding and certificate controls.
- Save separate certificates for configured hostnames and select them using TLS SNI. Validate certificate/key pairs and hostname coverage before saving. Per-host saves preserve every existing global TLS pair, which remains the default for connections without a matching SNI override. Only the first hostname certificate initializes the default when none exists; default renewal is an explicit action.
- Add authenticated, revision-checked APIs for hostname bindings and domain certificate configuration, with separate configuration read/write permissions.

## Upgrading

PostPlus **0.3.1 and newer** can update directly. Configuration, accounts, mail, queues and existing certificate files are preserved. Version 0.5.1 is now a prerelease; use 0.5.2 for stable upgrades.

Installations without an explicitly configured administration hostname keep compatibility access. Generated URLs retain the 0.5.0 bind/mail-server-hostname rules unless an explicit Webmail binding or shared hostname is configured. Review **Domains → Login addresses** before enabling hostname isolation. After setting a Webmail binding, publish A/AAAA records for that hostname and install or request a certificate covering it in the domain's TLS section.

Certificate issuance requires the certificate authority's DNS and HTTP-01 reachability checks. Staging certificates are not publicly trusted. Saving certificate paths applies them through the supervisor restart flow; independently launched services require a manual restart. A reverse proxy terminating HTTPS must also use a valid certificate for its public hostname.

The first-run wizard still configures one mail domain without automatically enabling login hostname restrictions. Add further domains through the domain wizard and verify their DNS before activation. The first domain and existing account/mail data remain protected from domain removal.
