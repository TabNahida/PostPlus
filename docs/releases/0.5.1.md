## Changes

- Replace the additional-domain text field with a dedicated **Domains** page,
  searchable domain list, pagination, and an **Add domain** wizard. Register a
  pending domain, publish its DNS records, check DNS, then activate it. Pending
  domains can be resumed later. First-run setup still configures one domain.
- Remove the 50-domain count limit. Each active domain hosts independent
  mailbox addresses on the same server; domains share mail listeners and the
  configured mail server hostname. Configuration size limits remain in place.
- Restrict administration and its API to one configured hostname, defaulting
  to the first domain. Webmail at `a.com` accepts only `@a.com` accounts.
  Configure an optional shared Webmail hostname to accept all active domains.
- Apply portal restrictions to password login, sessions, mailbox API keys and
  invitation registration. Browser sessions are bound to their login hostname;
  forwarded Host headers do not override the configured routing rules.
- Add domain lifecycle APIs with revision conflict detection, DNS diagnostics,
  activation checks and administrator API-key permissions. Domain deletion
  preserves accounts and mail, and protects the primary domain.
- Organize domain configuration and login addresses into separate sections,
  with English and Simplified Chinese labels, responsive layouts, and clear
  DNS, activation and restart feedback.

## Upgrading

PostPlus **0.3.1 and newer** can update directly. The updater preserves
configuration, accounts, mail, queues, certificates and keys. Existing primary
domains and 0.5.0 `additional_domains` are imported as active domains; their mail
does not need to be revalidated to continue operating.

Review **Domains → Login addresses** after upgrading. The default public
administration hostname is the primary mailbox domain. Webmail now uses the
visited mailbox domain, unless a shared Webmail hostname is configured. API
clients must use the appropriate hostname too. Explicit loopback development
access remains available with `allow_insecure_auth`.

Every public browser hostname needs A/AAAA records and TLS certificate coverage.
Adding a mail domain does not automatically issue a certificate. The native
HTTPS listeners use the configured certificate, which must cover all public
portal names you expose. DNS checks do not verify certificate coverage or
guarantee external reachability or mail delivery.

Domain activation and removal restart affected services through the native
supervisor. Independently launched services require a manual restart. Keep a
private backup before upgrading. Installations running **0.3.0** must first
install [0.3.1](https://github.com/TabNahida/PostPlus/releases/tag/v0.3.1) manually.
