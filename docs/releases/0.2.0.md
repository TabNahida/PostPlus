# PostPlus 0.2.0

PostPlus can now send mail directly from your server and sign it with DKIM,
without a separate SMTP relay. The DNS guide generates the records needed for
the configured server and checks their published values.

## Changes

- Built-in outbound SMTP resolves recipient MX records, tries destinations in
  preference order, and uses verified STARTTLS when offered. Required TLS is
  available. Temporary failures retry for five days by default; permanent
  failures and expired messages remain visible in the administration queue.
- Local RSA-2048 DKIM signing uses RSA-SHA256 and relaxed canonicalization.
  Setup and administration generate or load a private key and export its real
  public TXT record. Keys persist across retries and restarts and are included
  in private backups. External SMTP submission requires authentication.
- The DNS guide separates mailbox domain from server hostname, suggests
  `mail.example.com`, and groups receiving, sending authentication, DMARC and
  certificate instructions. Direct mode generates SPF from the entered public
  sending IPs and shows the actual DKIM public record. Public DNS checks show
  expected values, observed values and per-record status, with stale results
  discarded after input changes. Chinese desktop and mobile layouts are updated.
- Let's Encrypt HTTPS connections load distribution CA stores on Ubuntu/Debian
  and other Unix systems with statically linked OpenSSL. DNS, connection, TLS,
  timeout and malformed authority-response failures now report actionable
  errors instead of a generic initial-configuration error.
- Direct delivery rejects private or special-use destination addresses and
  foreign envelope sender domains, enforces signed message-size limits, pins
  validated destination IPs, and bounds DNS/SMTP transactions. Failed TLS
  upgrades never retry in plaintext. Final SMTP DATA acceptance completes
  delivery immediately.

## Upgrade and deployment

Stop PostPlus and back up the configuration, data and referenced secrets before
replacing the complete program directory. Preserve the existing configuration
and data paths. Older configurations without `outbound_mode` retain relay mode
when a relay host is configured, otherwise outgoing delivery remains disabled.

For direct sending, select **Built-in direct delivery**, set a public SMTP
hostname, generate/load DKIM and publish the displayed SPF/DKIM/DMARC records.
Allow outbound TCP 25 and DNS UDP/TCP 53 to the resolver, and ask your hosting
provider to set the sending IP's PTR to the mail hostname. A/AAAA should resolve
that hostname back to the sending IP. DNS matches do not guarantee IP reputation
or inbox delivery. See the [Chinese deployment guide](https://github.com/TabNahida/PostPlus/blob/v0.2.0/docs/getting-started.zh-CN.md)
or [English guide](https://github.com/TabNahida/PostPlus/blob/v0.2.0/docs/getting-started.md).

Incoming SPF/DKIM/DMARC verification, automatic delivery-failure messages,
MTA-STS/DANE and automatic certificate renewal are not implemented. Interrupted
final acknowledgements can cause duplicate outbound delivery after a retry.

## Downloads

Verify the downloaded archive against `SHA256SUMS`, extract it and run
`postplus` (`postplus.exe` on Windows) from the extracted directory.

| Package | Platform |
| --- | --- |
| `postplus-0.2.0-windows-x64.zip` | Windows 10+, x64 |
| `postplus-0.2.0-linux-x86_64.tar.gz` | Ubuntu 24.04 / compatible glibc 2.39+ and GCC 13 C++ runtime, x86_64 |
| `postplus-0.2.0-macosx-arm64.tar.gz` | macOS 15+, Apple Silicon |

Older systems and other architectures can build from source. The macOS package
is unsigned and not notarized. The release workflow verifies native tests,
integration tests and initialization of each extracted package before publishing.
