# PostPlus 0.1.1

This update makes remote first-run setup, account entry, and Linux service
installation easier.

## Changes

- Interactive first launch offers `127.0.0.1` for local setup or `0.0.0.0` for
  remote setup. Direct remote HTTP setup works without an existing TLS
  certificate; optional setup HTTPS is still available. The one-time setup
  password and Host/Origin checks continue to protect the wizard.
- The first administrator form and administration login now fill in the mail
  domain, matching account creation and Webmail login. Enter only the mailbox
  name, or paste a complete address on the displayed domain.
- Linux packages include `scripts/install-systemd.sh` to install a completed
  setup as a systemd service, enable startup at boot, and restart after failure.
  See [the service guide](https://github.com/TabNahida/PostPlus/blob/v0.1.1/docs/systemd.md)
  for installation and operation.

## Download and start

Verify your archive with the release's `SHA256SUMS`, extract it, and run
`postplus` (`postplus.exe` on Windows) from the extracted directory.

| Package | Platform |
| --- | --- |
| `postplus-0.1.1-windows-x64.zip` | Windows 10+, x64 |
| `postplus-0.1.1-linux-x86_64.tar.gz` | Ubuntu 24.04 / glibc 2.39+, x86_64 |
| `postplus-0.1.1-macosx-arm64.tar.gz` | macOS 15+, Apple Silicon |

Existing installations load their saved configuration as before. For direct
remote setup, use `./postplus --setup-bind 0.0.0.0 --setup-host SERVER-IP` and
open the printed address. Remote HTTP setup sends setup credentials without
encryption; use a trusted network, an SSH tunnel, or the optional setup TLS
files when encryption is needed. Public mail and web service TLS requirements
continue to apply after setup.
