# PostPlus 0.3.0

PostPlus 0.3.0 adds standard mail-client ports and configuration discovery,
incremental native updates, mailbox invitations, local wildcard forwarding,
scoped API keys, and one-click verification-code copying in Webmail.

## Changes

- New configurations use SMTP 25, POP3 110, IMAP 143, and Webmail 80 or HTTPS
  443. Setup and administration offer **Apply standard ports** for existing
  installations. Dedicated SMTP submission ports 587/465 and encrypted
  IMAP/POP3 ports 993/995 start when a TLS certificate and private key are
  configured. Submission requires both authentication and TLS.
- **Connect mail apps** shows the full mailbox username, incoming/outgoing
  hostname, ports and encryption settings. The DNS guide includes optional
  client-discovery SRV records. Thunderbird-style autoconfig and POX
  Autodiscover endpoints describe standard IMAP/POP3/SMTP settings; Exchange
  is not implemented, and IMAP retains its documented command subset.
- The mail hostname, such as `mail.example.com`, drives the Webmail link,
  certificate request and client settings. The guide follows configured values
  rather than linking users to the bare mailbox domain.
- **Update PostPlus** checks official stable releases, previews changed files,
  downloads verified modules, and applies the prepared update. Source
  fingerprints preserve unchanged components; only affected services restart.
  Shared core or dependency changes also update their consumers, and launcher
  changes restart the whole group. Configuration, mail, accounts, queues,
  certificates and private keys are preserved. Readiness failures restore the
  previous modules and version record. Downloads do not interrupt services;
  applying affected modules briefly closes their connections.
- Webmail folder badges show unread counts for Inbox, Junk and Archive, and
  unsent draft counts for Drafts. Sent and Trash have no numeric badges.
- Webmail detects the latest confidently identified verification code in up to
  30 recent Inbox messages from the past 15 minutes and offers one-click copying.
  `GET /api/verification-code` accepts a mailbox API key with `codes:read`.
  Lookup does not mark messages read. Attachments, quoted/forwarded content,
  hidden HTML and ambiguous candidates are excluded; the display window is
  not a guarantee of the sender's code validity.
- **Administration → User accounts** creates mailbox invitation links with an
  expiry, use limit and optional assigned mailbox name. Invitations can be
  revoked. Registration validates the live password policy and atomically
  consumes a use only when account creation succeeds.
- **User accounts** also manages local wildcard forwarding with `*` and `?`.
  Targets must be existing accounts in the configured domain. Exact mailbox
  matches take priority. Queued recipients retain their chosen destination,
  equivalent destinations are deduplicated, and original message headers are
  preserved. External forwarding is not included.
- Administrator API keys have explicit read/write permissions for individual
  operations. Webmail users can create keys limited to their own mailbox with
  `mailbox:read`, `mailbox:write`, `mailbox:send` and `codes:read`. Permissions and
  revocations apply immediately without rotation or restart. Key management
  requires a browser session and CSRF protection; raw keys are displayed once.
  Existing administrator keys migrate with their previous full permissions.
  API clients creating keys must now provide an explicit `permissions` array.

## Upgrade compatibility

Upgrade from 0.2.1 by installing the complete 0.3.0 package once, retaining
configuration and data. The published 0.2.1 has no online updater. Back up
databases before starting 0.3.0: its account schema migrates to version 4,
which older authentication binaries cannot read. A manual downgrade to 0.2.1
requires restoring the pre-upgrade account database as well as the old binaries.

Existing explicitly saved ports remain unchanged. Missing secure-client port
fields default to 587, 465, 993 and 995 and become active when TLS files are
configured, including existing installations. Check for port conflicts and
firewall rules, or explicitly set unwanted dedicated listeners to `0`.

## 中文升级提示

0.3.0 新增标准端口及客户端连接/DNS 引导、按模块在线升级、最新验证码复制与
API、邀请注册、本域通配符转发和 API key 权限管理；Webmail 数字提醒改为未读数
及未发送草稿数。

从已发布的 0.2.1 升级时，需先手动安装一次完整 0.3.0，因为旧程序没有在线升级
功能。停止 PostPlus，备份配置、数据和引用的证书/私钥，再替换完整程序及 `web`
目录，保留原配置与数据路径。完整安装包包含 `postplus-update.json` 组件基线，
后续可在管理后台“服务器设置 → 升级 PostPlus”检查、下载并应用新版。

已有配置中的自定义端口不会自动改变。需要标准端口时，在后台点击“应用标准
端口”，检查后保存。公网收信必须开放 TCP 25；客户端安全收发信还需配置覆盖
邮件主机名的 TLS 证书，并放行对应的 587/465、993/995 端口。DNS 的 MX 记录
不能指定端口。DNS 自动发现为可选项，客户端必要时仍需手动配置。
旧配置若已设置 TLS 且缺少新增客户端端口字段，会按默认值启用 587、465、993、
995；请检查端口占用及防火墙，不需要的专用监听可显式设为 `0`。

通过项目脚本注册的 systemd 安装，应在替换完整发行版后，按原配置路径和服务
账户重新运行一次 `sudo bash scripts/install-systemd.sh`。新版 unit 配置启动前
恢复助手，使启动器升级失败时可以恢复旧版本；用
`systemctl cat postplus.service` 确认 `ExecStartPre` 恢复项。运行账户还需要对
安装目录、网页和数据目录有写权限。旧管理员 API key 保留原权限，可在后台
按用途收紧；通过 API 新建 key 时，必须明确传入 `permissions`。
账户数据库会迁移至 schema 4，旧认证程序无法读取；若手动回退至 0.2.1，需同时
恢复升级前的账户数据库备份。详情见
[升级指南](https://github.com/TabNahida/PostPlus/blob/v0.3.0/docs/updates.md)、
[客户端配置](https://github.com/TabNahida/PostPlus/blob/v0.3.0/docs/mail-clients.md)和
[邀请、转发与 API 权限](https://github.com/TabNahida/PostPlus/blob/v0.3.0/docs/access.md)。

## Downloads and validation

The release workflow builds and tests Debug/Release on Linux, Windows and
macOS, then extracts and runs each native package before publication. All
verification and packaging jobs must pass before the release is published.
Local Ubuntu full integration regression, Windows feature/unit tests and
frontend checks passed before tagging.

| Complete package | Platform |
| --- | --- |
| `postplus-0.3.0-windows-x64.zip` | Windows 10+, x64 |
| `postplus-0.3.0-linux-x86_64.tar.gz` | Ubuntu 24.04 / compatible glibc 2.39+ and GCC 13 C++ runtime, x86_64 |
| `postplus-0.3.0-macosx-arm64.tar.gz` | macOS 15+, Apple Silicon |

Verify the complete archive against `SHA256SUMS`, extract it and run `postplus`
(`postplus.exe` on Windows). Keep the full extracted directory together.
Individual module assets and `postplus-update.json` are consumed by the native
updater. Other architectures and older systems can build from source. The
macOS package is unsigned and not notarized.
