# PostPlus 新手入门

[English guide](getting-started.md) · [配置文件参考](configuration.md) · [返回首页](../README.md)

这份指南先带你在一台电脑上创建两个邮箱并互相发信，再介绍远程管理、真实域名、TLS 证书、外发中继和日常维护。第一次试用不需要提前编写配置文件。

## 1. 编译并启动

先安装 [xmake](https://xmake.io/) 2.9.8 或更新版本，以及支持 C++20 的编译器：

| 系统 | 准备工作 |
| --- | --- |
| Windows | 安装 Visual Studio 2022 或更新版本，勾选“使用 C++ 的桌面开发”和 Windows SDK。 |
| Linux | 安装 GCC 12 或更新版本，或支持 C++20 协程的 Clang，以及 Git、Make 等常用开发工具。 |
| macOS | 安装 Xcode Command Line Tools；尚未安装时可执行 `xcode-select --install`。 |

在 PostPlus 仓库目录打开终端，依次运行：

```sh
xmake f -m release -y
xmake build -y
xmake run postplus
```

第一次编译需要下载和构建依赖，耗时通常比后续编译长。启动后请保持终端打开；按 **Ctrl+C** 会停止主程序及其管理的全部服务。不需要 Python 启动脚本，也不需要另外安装 Web 服务器。

如果使用已经编译好的程序，请把 `postplus`、所有 `postplus-*` 服务程序和 `web` 目录放在一起，从该目录运行主程序。Windows 的主程序是 `postplus.exe`。可以用 `--config` 指定配置文件位置；运行账户必须有权限在目标目录写入配置。

## 2. 打开配置页面，输入首次配置密码

尚未配置的安装会在终端明确提示需要配置，并给出：

- **配置网址**：默认是 `http://127.0.0.1:8081/`。
- **首次配置密码**：当前主程序随机生成，用于解锁配置页面。

在运行 PostPlus 的同一台电脑上打开网址，把终端中的密码填入页面。不要使用邮箱密码替代它。如果还没配置完成就重启主程序，需要使用重新生成的密码。

这里有三种不同用途的凭据：

| 凭据 | 用途 | 从哪里获得 |
| --- | --- | --- |
| 首次配置密码 | 解锁本次安装向导 | 主程序终端临时显示 |
| 管理员密码 | 之后登录管理后台和该账户的 Webmail | 你在向导中自己设置 |
| 内部服务令牌 | 供各个服务进程相互认证 | 向导自动生成并保存在私有文件里，无需输入网页 |

页面默认英文，可以用语言选择器切换为 **简体中文**，浏览器会记住选择。

### 已经存在配置文件时

默认配置路径为 `config/postplus.json`。使用向导前不必复制示例文件。缺少配置，或已有示例未填写服务令牌文件路径、没有有效令牌环境值且没有 `setup_complete` 标记时，会进入向导；已经初始化的安装会直接按原配置启动。JSON 格式错误、文件不可读或配置引用的凭据文件损坏时，主程序会报错，需要修正对应问题。

不要为了修改设置或找回密码而删除已有安装配置。完成初始化后应使用后台管理或下面的恢复步骤。如果想单独试验另一套安装，可使用不同配置文件，但也要在页面选择**不同的数据目录和未占用的端口**：

```sh
xmake run postplus --config "config/trial.json" --setup-port 8082
```

### 服务器没有浏览器时

`127.0.0.1` 指的是浏览器所在的电脑，并不代表远程服务器。首次配置只监听服务器本机回环地址。可以在自己的电脑上通过 SSH 转发访问：

```sh
ssh -N -L 8081:127.0.0.1:8081 server-user@server-address
```

把 `server-user` 和 `server-address` 换成服务器登录账户及地址。保持 SSH 连接，在本机浏览器打开 `http://127.0.0.1:8081/`，输入**服务器 PostPlus 终端**显示的首次配置密码。

如果使用了其他配置端口，把命令里的两个 `8081` 都换成那个端口。向导会校验访问的 Host/Origin，请保持转发前后的端口一致。使用这种方式不必把配置端口开放到公网。

完成配置后，只要 `admin_bind` 仍为 `127.0.0.1`，这个隧道也可以访问管理后台。启用 TLS 后，后台改用 HTTPS；浏览器使用的主机名仍要与证书匹配，SSH 隧道不会取消证书校验。

## 3. 完成首次配置

第一次在本机试用时，可以按照下表填写；其他选项先保留默认值。

| 配置区域 | 本机试用建议 | 含义 |
| --- | --- | --- |
| 服务器身份 | 域名填 `localhost` | 邮箱会是 `alice@localhost`，只能用于本地试用，不能接收互联网来信。 |
| 首个管理员 | `admin@localhost`，设置新密码 | 建议至少 12 个字符，保存在密码管理器中。 |
| 数据目录 | 保留建议路径 | 存放账户、邮件、投递队列和默认日志，应位于可写的持久磁盘上。 |
| 连接与安全 | 保留回环监听，启用本地开发模式 | 可以在本机无证书试用；其他电脑不能用这种模式明文登录。 |
| 后台管理端口 | `8081` | 配置服务器和管理账户的页面。 |
| Webmail 端口 | `8080` | 浏览器收发邮件的页面，与后台管理分开。 |
| SMTP / POP3 / IMAP | `2525` / `1110` / `1143` | 邮件客户端的测试端口，通常不需要管理员权限绑定。 |
| 内部服务端口 | 保留默认 | 服务进程相互通信使用，所有端口必须互不相同。 |
| 外发中继 | 暂时不填主机 | 可以向本地域名内的账户发信；发送到其他域名需要配置中继。 |
| ClamAV | 试用时暂时不填主机 | 内置规则仍生效；完整杀毒需要另外安装 ClamAV。 |

保存后，PostPlus 会校验配置、创建管理员和私有配置文件、关闭向导并启动正常服务。使用成功页面或终端给出的链接继续。

向导会自动创建内部服务令牌文件，并把路径写入 `service_token_file`。通过向导创建的安装无需手动设置 `POSTPLUS_SERVICE_TOKEN`。管理员密码以加盐哈希形式存入认证数据库，配置文件中不会保存管理员明文密码。

## 4. 创建用户，发出第一封邮件

1. 本机试用时打开后台：`http://127.0.0.1:8081/`。
2. 使用向导创建的管理员邮箱地址和**永久管理员密码**登录。
3. 进入 **User accounts / 用户账户**，创建 `alice@localhost` 和 `bob@localhost`，分别设置至少 12 个字符的密码。普通用户不要勾选管理员权限。
4. 打开 Webmail：`http://127.0.0.1:8080/`，使用 Alice 的账户登录。
5. 新建邮件，收件人填 `bob@localhost`，输入主题和正文后发送。
6. 退出 Alice，使用 Bob 登录，刷新收件箱。邮件通过队列投递，可能需要短暂等待。

用户名始终填写完整邮箱地址，不能只填 `alice`。Webmail 不提供公开注册，所有账户由管理员创建。管理员自己的邮箱也可以单独登录 Webmail。

如果未收到邮件，在后台 **Delivery queue / 投递队列** 查看状态，再到 **Service logs / 服务日志** 查看错误。目前没有“已发送”文件夹，发件账户不会自动留下一份已发送副本。

### 连接邮件客户端

客户端自动发现尚不完善时，请手动配置：

| 客户端设置 | 本机试用值 |
| --- | --- |
| 用户名 | 完整邮箱地址，例如 `alice@localhost` |
| 密码 | 对应账户的永久密码 |
| 收信服务器 | `127.0.0.1` |
| 收信协议和端口 | IMAP `1143`，或 POP3 `1110` |
| 发信服务器 | `127.0.0.1`，SMTP 端口 `2525` |
| 本机试用加密方式 | 无，仅限明确启用的回环开发模式 |
| TLS 部署加密方式 | SMTP、IMAP 选择 STARTTLS；POP3 选择 STLS/STARTTLS |
| SMTP 认证 | 开启，使用完整邮箱地址和密码 |

正式配置后，应替换为实际服务器主机名及配置的端口。面向邮件客户端的隐式 TLS 监听（如 SMTP 465、IMAP 993、POP3 995）目前未实现，单纯把端口改成这些数字不会启用这种加密方式。IMAP 的文件夹、IDLE 等功能也仍在开发，请先查看[协议支持表](protocols.md)。外发中继支持的隐式 TLS 是另一项功能。

## 5. 从管理后台修改服务器设置

在 **Server settings / 服务器设置** 调整域名、监听地址、端口、TLS、外发中继、过滤、容量限制、会话和日志。页面会说明字段含义，并校验类型、数值范围和端口冲突。

保存会写入配置并创建备份，**不会自动重启服务**。当前服务和网页会话继续使用正在运行的设置。准备好应用改动时：

1. 记下设置页面显示的新后台和 Webmail 网址。
2. 在主程序终端按 **Ctrl+C**，等待全部服务退出。
3. 再次运行原来的启动命令；此前使用了 `--config` 时，保留相同参数。
4. 等待启动完成，打开新的后台网址并重新登录。停止服务前的旧会话已失效。

如果新地址、端口或证书导致启动失败，修正配置文件或恢复保存时生成的备份，再启动。主程序会报告错误，不会自动回滚已保存的配置。

初始化后，数据目录在页面中只读。它存放真实账户和邮件，迁移需要停止全部服务、完整复制目录并手动修改配置。**修改域名不会自动重命名已有账户或迁移邮箱**，应尽量在创建实际用户前确定域名。

只在配置文件中提供的高级项，以及手动编辑方法，请看[配置参考](configuration.md)。如果自行单独启动各服务，而没有使用 `postplus` 管理进程，保存后需要自己重启各服务。

## 6. 配置真实域名、DNS 和 TLS

假设你拥有 `example.com`，希望邮箱地址为 `alice@example.com`，服务器主机名为 `mail.example.com`。

1. **确定邮箱域名。** PostPlus 的 `domain` 填 `example.com`，即邮箱 `@` 后面的部分。它可以与服务器主机名不同。目前一套安装支持一个邮箱域名。
2. **配置 DNS。** 在域名服务商处给 `mail.example.com` 添加指向服务器公网 IPv4 的 A 记录。只有 IPv6 确实能访问监听地址时才添加 AAAA。若要直接接收互联网邮件，给 `example.com` 添加 MX 记录，目标为 `mail.example.com`。MX 填主机名，不填 IP、网址或端口号。
3. **安排入站 SMTP。** 其他邮件服务器默认连接 TCP 25。测试用 `2525` 不会被 MX 记录自动发现，需要配置可用的 25 端口监听或受控转发。确认云服务商、防火墙和路由器允许连接。在后台填端口并不会自动设置防火墙/NAT，也不会赋予进程绑定低端口的系统权限。
4. **准备证书。** 使用证书服务商或 ACME 客户端获取覆盖 `mail.example.com` 的 PEM 证书链及匹配的、未加密的 PEM 私钥。文件必须位于服务器上，并且运行 PostPlus 的账户能读取。私钥应限制访问权限。PostPlus 不会自动申请或续签证书。
5. **设置监听和 TLS。** 在后台填写证书及私钥路径，关闭本地明文认证，设置可访问的监听地址。`0.0.0.0` 代表全部 IPv4 网卡，`127.0.0.1` 代表仅限本机。通过隧道管理时可让后台继续仅监听回环地址。所有服务端口必须不同，后台与 Webmail 也不例外。
6. **用证书对应的主机名访问。** 例如 Webmail 端口仍为 8080 时，访问 `https://mail.example.com:8080/`。用 IP 或其他名称访问可能触发证书名称不匹配。各 TLS 监听使用同一组配置的证书及私钥。
7. **设置外发中继。** 按下一节填写，再创建真实域名的账户。先测试本地互发成功，再测试外部收件人。

向导会检查本机配置，不会证明公网是否可达，也不会替你申请域名、配置 DNS、开放防火墙或保证外部邮箱接受来信。后台与 Webmail 端口分开，可以让后台留在管理网络中。

### 向外部邮箱发信：配置 SMTP 中继

外发中继（smarthost）是接收你的邮件并继续向外转发的 SMTP 服务，可以由邮件服务商或另一台服务器提供。PostPlus 当前不会自行查找目标域名的 MX 并直接投递。

在服务器设置中填写：

- 服务商提供的中继主机和端口，常见为 `587` 搭配 `starttls`，或 `465` 搭配 `implicit`。
- 需要认证时填写中继用户名。
- 在密码框填写中继密码。它会被保存到私有凭据文件，不会在页面再次显示；以后修改配置时留空表示保留已保存的密码。

也可以通过环境变量提供密码，默认名称为 `POSTPLUS_SMARTHOST_PASSWORD`，并在页面的环境变量项填写这个**名字**。非空的环境变量值优先于已保存密码。请在启动 PostPlus 的进程环境或系统服务的受保护环境配置中设置其值，再重启主程序。避免把真实密码写进会保存历史记录的命令行。`service_token_file` 是 PostPlus 内部凭据，不能用来登录外部中继。

外发 TLS 会验证中继证书链及主机名。若系统需要显式指定信任证书库，可在启动前配置 OpenSSL 的 `SSL_CERT_FILE` 或 `SSL_CERT_DIR`。域名验证、发信权限、SPF/DKIM 等应按中继服务商要求设置；PostPlus 自身尚未实现 SPF、DKIM 签名或 DMARC 处理，需要时应使用中继提供的能力。

### 反垃圾规则和 ClamAV 杀毒

后台可以设置禁止词和垃圾评分阈值。内置功能是基础规则过滤，不是训练好的垃圾邮件分类器。被拒绝的邮件保存在隔离队列；修改规则不会自动释放已隔离邮件。

完整杀毒需要另行安装 ClamAV、维护病毒库，并让 PostPlus 能访问支持 INSTREAM 的 `clamd` 服务。填写 `clamav_host`、`clamav_port`（通常 `3310`）和超时时间。内置 EICAR 检测只是测试签名检测，不能替代完整杀毒。扫描服务故障会延迟投递并重试，不会把未完成扫描当作安全邮件。启用后请检查过滤日志及投递队列。

## 7. 停止、备份与恢复

在主程序终端按 **Ctrl+C**，等待全部服务退出。做一致的离线备份时，应完整复制数据目录、配置文件、它引用的内部令牌文件和 TLS 凭据，并把备份放在受保护的位置。不要只复制正在运行的 `.sqlite3` 文件：最新数据可能仍在 WAL 文件中。详细说明见[备份与恢复](architecture.md#backup-and-recovery)。

恢复或手工编辑后，用相同的 `--config` 路径重新启动，检查终端输出。在新配置成功启动前保留原配置或保存时生成的备份。若后台因地址或端口配置错误无法访问，停止主程序，在文件中修正 `admin_bind`、`ports.admin` 或 TLS 路径，再启动。

忘记管理员密码时，可以在服务仍运行的情况下通过本机命令行重设：

```sh
xmake run postplus-ctl password admin@example.com --config config/postplus.json
```

把地址替换成实际管理员地址，按提示输入新密码，不要把密码放进命令参数。此操作要求能够读取安装的内部服务凭据。该账户在后台及 Webmail 中的旧会话会在下一次认证请求时失效。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 没有首次配置提示 | 检查本次使用的配置路径。已经初始化的安装会直接启动，应打开后台地址。新试验使用独立配置和数据目录。 |
| 首次配置密码错误 | 使用当前运行主程序显示的密码；重启会生成新密码。复制时不要附加空格。 |
| 本机能打开配置页，其他电脑不能 | 首次配置仅监听回环地址；使用前面的 SSH 转发方法。浏览器的 `127.0.0.1` 指本机。 |
| 提示端口不可用或地址已占用 | 检查另一实例或其他软件是否占用端口，停止冲突程序或换端口。后台与 Webmail 不能共用端口。 |
| `setup web asset is missing` | 重新编译，保留可执行文件旁的完整 `web` 目录，或用 `--web-root` 指向仓库的 `web` 目录。 |
| 缺少服务令牌或令牌错误 | 检查令牌文件路径和读取权限；非空的令牌环境变量会优先于文件。恢复正确凭据，不要因此替换已有数据目录。 |
| 登录提示需要 TLS | 配置证书；仅本机试用时可明确开启回环开发模式。公网明文登录不受支持。 |
| TLS 文件校验失败 | 使用服务器上可读的 PEM 证书链和匹配的未加密 PEM 私钥，检查路径和运行账户权限。 |
| 浏览器提示证书错误 | 使用证书覆盖的主机名，检查证书有效期及信任链。邮箱域名不一定等于 TLS 主机名。 |
| 已保存的设置没有生效 | 保存不会重启服务。按 Ctrl+C 停止并等待退出，再运行原启动命令；启动后使用新网址。 |
| 重启后网页断开 | 服务停止会使原会话失效。等待启动后，使用新的后台网址重新登录，失败时查看主程序终端。 |
| 邮件没到 | 确认收件人存在，检查投递队列，再查看 storage/delivery/filter/transfer 日志。外部收件人还需要中继。 |
| 启用杀毒后邮件一直等待 | 确认 `clamd` 运行、端口可达、病毒库已加载；扫描故障会延迟投递。 |
| 外部邮箱无法投递进来 | 检查 MX/A/AAAA、TCP 25、防火墙/NAT、服务商限制及本地收件账户。 |
| 邮件客户端缺少文件夹等功能 | 对照[协议支持表](protocols.md)；完整 IMAP 兼容仍在开发。 |

更多细节见[配置参考](configuration.md)、[架构与运行维护](architecture.md)和 [HTTP API](api.md)。
